## 用户需求

用户反馈：简报中心「数据源管理 / 订阅管理 / 关注点管理 / Generate 生成简报」四个 tab 面板，每张卡片（`.bf-panel` 外壳 + `.bf-label` 标题）与下方对应的内容（折叠区、空状态提示）视觉上「像分离了」，像多张叠放的卡片。

## 产品概述

当前每个 tab 面板以内嵌 `.bf-panel` 卡片外壳呈现，标题行下挂载 Streamlit 原生 `st.expander` 折叠区与 `st.info` / `st.warning` 状态提示。目标是让「标题 + 折叠区 + 空状态」读起来是**同一张卡片内部的分区**，而非三块独立卡片。

## 核心特征

- 卡片外壳 `.bf-panel` 保留为唯一卡片容器（彩色顶边、圆角、轻阴影）。
- 卡片内的 `st.expander` 折叠区仅作为「可折叠内部分区标题行」，去掉独立卡片感（已有基础，需强化）。
- 卡片内的 `st.info` / `st.warning` 空状态/不可用提示不再渲染为独立蓝色/黄色块，改为卡片内轻量提示（去独立背景，仅保留左侧细色条）。
- 标题与首个折叠区/提示之间由「14px 大空隙」改为「细分隔线贴合」，消除标题悬浮感。
- 仅调整视觉样式，不改动业务交互逻辑，保留 `st.expander` 折叠能力。

## 技术栈

- 前端框架：Streamlit（Python），通过注入 `styles.py` 中的 CSS 覆盖默认组件样式。
- 样式体系：项目已有 `intelnexus/core/ui/styles.py` 集中管理 CSS 变量（`--wb-card` / `--wb-border` / `--wb-text-*` / `--wb-tag-*`）与 `.bf-panel` / `.bf-label` 系列类。
- 复用约定：所有面板在 `intelnexus/ui/briefing_viewer.py` 中以 `st.markdown('<div class="bf-panel ...">')` 开壳、`st.markdown('</div>')` 收壳，内部直接使用 `st.expander` / `st.info` / `st.warning`。

## 实现思路

采用「CSS 为主、代码替换为辅」的去卡片化方案，分两层解决分离感：

1. **CSS 层（styles.py）**：在 workbench 作用域内，针对 `.bf-panel` 内的 alert 容器（`.stAlert` / `[data-testid="stAlertContainer"]` 及其子 div）去除独立背景与边框，仅保留细左侧色条（`border-left`），并将文字色改为 `--wb-text-secondary`，使 `st.info` / `st.warning` 像卡片内一段轻提示。同步把 `.bf-label` 与首个 expander 之间的 `margin-top:14px` 改为 `0` 并加 `1px` 细分隔线（`border-top`），让标题与内容贴合成同一卡片的两个区域。
2. **代码层（briefing_viewer.py）**：将 4 处 `st.info` 空状态（数据源/订阅/关注点/历史）替换为 `st.markdown` 自定义段落（复用 `--wb-text-secondary`、无背景），从源头消除 alert 块；`st.warning` 模块不可用提示同样改为轻量 markdown，避免黄色块割裂。

## 关键技术决策

- **为何 CSS + 代码双管齐下**：纯 CSS 覆盖 `st.info` 依赖 Streamlit 版本 testid 稳定性，存在升级失效风险；代码层替换为 markdown 是更根本的解决，二者并存可互为兜底，且改动局部、不影响折叠逻辑。
- **为何保留 expander 仅弱化样式**：`st.expander` 折叠能力是核心交互，不能改为纯 `st.container`；已存在 `styles.py:1063-1113` 去边框化处理，本方案在其基础上补强 summary 行与首间隙，避免重构成本。
- **性能**：仅静态 CSS 与 markdown 渲染，无额外计算/网络开销；不影响 Streamlit 重跑性能。
- **避免技术债**：严格沿用现有 `.bf-panel` 外壳模式与 CSS 变量，不引入新组件或新样式文件。

## 实现注意

- CSS 选择器需同时覆盖 class（`.stAlert`）与 testid（`[data-testid="stAlertContainer"]`），并以 `!important` 压制 Streamlit 默认样式，与现有 `styles.py:1079-1113` 风格一致。
- 替换 `st.info` 为 `st.markdown` 时保留原文案（`get_text(...)`），仅改渲染方式，不触碰 i18n key。
- 改动后需以 `python -m py_compile` 校验两个文件语法，并用 `read_lints` 确认无报错。
- 4 处 `st.warning`（来源/订阅/关注点模块不可用）文案与位置保持，仅改渲染样式为轻量提示，避免误删 `return` 早退逻辑。

## 架构设计

不涉及新架构。沿用「`.bf-panel` 外壳 + 内部原生控件」模式，仅通过样式归一与渲染替换，使外壳与内部控件在视觉上归并为单一卡片。
