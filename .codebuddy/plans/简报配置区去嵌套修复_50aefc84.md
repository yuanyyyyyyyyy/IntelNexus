## 用户需求

简报中心 UI 重构（方案 A）运行后报 `StreamlitAPIException: Expanders may not be nested inside other expanders.`，需修复该错误。

## 产品概述

报错根因：`render_briefing_settings` 用外层 `st.expander` 包裹三个配置面板，而三个面板内部共 7 处二级 `st.expander`（新增/管理表单），违反 Streamlit「expander 不可嵌套 expander」的硬性约束。用户已确认修复方向：将外层配置区从 `st.expander` 改为 `st.container` + `st.toggle` 可见性开关，配置区由「可折叠」变为「常驻区块 + toggle 显隐」，面板内二级 expander 全部保留。

## 核心特性

1. 配置区外层 `st.expander` 改为 `st.container`，由 `st.toggle(get_text("briefing_settings"))` 控制区块显隐，toggle 状态与 `st.session_state.bf_expand_settings` 双向同步。
2. 三个面板（`render_data_sources_panel` / `render_subscriptions_panel` / `render_watch_categories_panel`）内部所有二级 `st.expander` 原样保留，不再嵌套报错。
3. 可点击引导条跳转逻辑不变：点击 step 设置 `bf_expand_settings=True` + `bf_active_tab` + `bf_switch_tab` 并 `st.rerun()`，toggle 下次渲染即反映展开。
4. 横向 `st.tabs` 组织三个面板 + `bf_switch_tab` 切换逻辑（`active_idx != 0` 时才 rerun）维持不变。
5. 现有 workbench 作用域 CSS（`.stTabs` / `[data-baseweb="tab-panel"]` / `.bf-panel` 在 tab 内收敛）不受 expander→container 结构变化影响，保留；按需补充容器区块与生成区之间的间距样式。

## 技术栈

- Python + Streamlit（UI 通过 `st.container` / `st.toggle` / `st.tabs` + 组件组合）
- 样式集中管理于 `intelnexus/core/ui/styles.py` 的 `render_workbench_css`（`:has(.bf-workbench-scope)` 作用域）

## 实现方案

### 改动 1：`render_briefing_settings` 去嵌套（briefing_viewer.py:551-579）

- 删除外层 `with st.expander(get_text("briefing_settings"), expanded=expand_state):`，改为：
- `expand_state = st.session_state.get("bf_expand_settings", False)`
- `with st.container():` 包裹整个配置区
- 在 container 顶部用 `st.toggle(get_text("briefing_settings"), value=expand_state, key="bf_settings_toggle")` 控制显隐；`on_change` 或直接读值后写回 `st.session_state.bf_expand_settings`
- `if not st.session_state.get("bf_expand_settings", False): return`（toggle 关闭时不渲染 tabs/面板，避免无谓渲染）
- 内部 `st.tabs` + 三个面板调用 + `bf_switch_tab` 切换逻辑完全保留
- 关键决策：用 toggle 替代 expander 是实现「可折叠配置区」且避开嵌套约束的最简方案；toggle 不引入新的 DOM 嵌套层级，面板内 expander 独立存在不冲突。

### 改动 2：`_render_onboarding` 点击同步（briefing_viewer.py:582-641）

- 已存在点击 step → `bf_expand_settings=True` + `bf_active_tab` + `bf_switch_tab` + `st.rerun()`。
- 注意：rerun 后 `render_briefing_settings` 读 `bf_expand_settings` 得 `True`，toggle 的 `value=expand_state` 即反映为开启，无需额外处理。
- 不改动 step 视觉卡片与负 margin 结构。

### 改动 3：`render_briefing_center` 注释更新（briefing_viewer.py:644-681）

- 调用顺序不变（引导条 → 生成区 → 配置区 → 结果区 → 历史 toggle）。
- 仅将 docstring 中「可折叠配置区（expander + 横向 tab）」改为「可折叠配置区（container + toggle + 横向 tab）」。

### 改动 4：styles.py 间距补充（可选，styles.py:912-922 区间）

- 现有 `.stTabs .bf-panel` margin 收敛与 tab 面板透明 CSS 基于 `.stTabs` 选择器，不受 expander→container 影响，保留。
- 若 container 化后配置区与上方生成区间距不足，在 `render_workbench_css` 内为 `.bf-workbench-scope` 直接子级 `stContainer` 补 `margin-top`，限定作用域避免污染其他页面。

## 实现备注

- 不改动 `render_briefing_generate_top`、三个面板函数内部逻辑、`_run_pipeline` / `_render_stats` 业务、历史 toggle 逻辑。
- 沿用 `bf_expand_settings` / `bf_active_tab` / `bf_switch_tab` 三个 session_state key。
- `bf_switch_tab` 的 rerun 守卫（`active_idx != 0`）保留，避免死循环。
- 验证：`python -m py_compile` 四个文件通过；用户在已装依赖环境运行 `run.bat ui` 进入简报中心，确认配置区 toggle 折叠/展开、面板内新增/管理表单 expander 可正常打开、引导条点击展开配置区并跳 tab、无嵌套报错。

## 架构设计

无新增架构模式。仅将配置区容器从 expander 降级为 container + toggle 控制显隐，数据流与 session_state 契约不变。
